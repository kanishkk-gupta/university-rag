# BMU University RAG

## Problem
General-purpose Large Language Models (LLMs) like Code Llama lack specific knowledge about private institutions. When asked about BML Munjal University's fee deadlines, holidays, or academic regulations, they either hallucinate or state they do not know. 

## Proposed Application
A "Five-Exercise" educational demonstration platform that exposes the exact mechanics of Retrieval-Augmented Generation (RAG). Instead of just answering questions, this application visualizes the hidden data flow—from raw PDFs to vector embeddings to LLM synthesis.

## Knowledge Source
The system ingests BMU's official documents located in the `documents/` directory (e.g., Student Handbook, Holiday Lists, Fee Calendars).

## How RAG Is Used
RAG solves the hallucination problem by mathematically searching the knowledge base for relevant chunks of BMU documents *before* asking the LLM to answer. These chunks are injected into the LLM's prompt context.

## Role of the LLM
The LLM (`codellama:7b-instruct`) acts solely as a reasoning and natural language synthesis engine. It reads the provided BMU context and formats a direct, grounded answer.

## Architecture
The system is built on a modern stack:
- **Frontend**: React + Vite (Minimalist, institutional aesthetic).
- **Backend/API**: FastAPI (Python).
- **Vector Store**: ChromaDB (Local).
- **Embeddings**: `all-MiniLM-L6-v2` via `sentence-transformers`.
- **LLM**: Local Ollama instance.

## Exercise 1 — LLM Application
Demonstrates the baseline failure of the LLM when operating without retrieval. Users can compare the "WITH RAG" and "WITHOUT RAG" responses side-by-side to understand the necessity of grounding.

## Exercise 2 — Knowledge Base
Visualizes the data ingestion process. Users can explore the extracted chunks for any document and inspect the actual 384-dimensional vector embeddings generated by the model, complete with a conceptual 2D vector space projection.

## Exercise 3 — Retrieval / RAG
A "Live Pipeline Mode" that traces a single query through 7 stages: Query -> Query Embedding -> Vector Similarity Matching -> Context Formulation -> LLM Generation -> Answer -> Source Citations.

## Exercise 4 — APIs / Services / Orchestration
Visualizes the microservice architecture. Includes an interactive request trace logger mapping how the Frontend communicates with the FastAPI layer, the RAG Service, ChromaDB, and Ollama.

## Exercise 5 — Docker
Provides the final container architecture for deploying the system, mapping volumes for persistent ChromaDB storage and connecting to the external Ollama host.

## Running the Application

### 1. Start the API
```bash
PYTHONPATH=. uvicorn api.main:app --host 0.0.0.0 --port 8000
```

### 2. Start the Frontend
```bash
export NVM_DIR="$HOME/.nvm" && [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"
cd frontend
npm run dev
```

## Demonstration
1. Navigate to the **LLM Application** view and search "What is the deadline for Odd Semester fee payment for existing students?". Observe the failure of the base model vs the success of the RAG pipeline.
2. Navigate to **Knowledge Base**, select the "Fee Payment Calendar", and inspect the chunks and raw vector values.

4. Navigate to **Orchestration** to view API traces.

## Project Structure
- `api/`: FastAPI routes and schemas.
- `rag/`: Prompt generation and LLM pipeline.
- `retrieval/`: Vector similarity searching.
- `vectorstore/`: ChromaDB persistent client.
- `ingestion/`: OCR and structural chunking.
- `embeddings/`: Sentence-transformer logic.
- `frontend/`: React Vite SPA.
